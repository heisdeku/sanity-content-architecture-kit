# Schema

Everything content-related lives in `sanity/` and imports only relatively. The
frontend imports from `sanity/` (queries, types, constants); never the reverse.

## Document roles

| type | role | route | tabs |
|------|------|-------|------|
| `homepage` | singleton, id `homepage` | `/` | Page, Content, SEO, Agents, Security |
| `page` | owns its full path in `uri` | `/about`, `/pricing/enterprise` | Page, Content, SEO, Agents, Security |
| `article` | publishing contract: excerpt, cover, categories, author, publishedAt | `/articles/<slug>` | Article, Content, SEO, Agents, Security |
| `category` | taxonomy, no route | none | single tab |
| `legalPage` | body + lastUpdated, promotional sections blacklisted | `/legal/<slug>` | Legal, Content, SEO, Agents, Security |
| `submission` | generated by the contact form, fully read-only | none | single tab |
| `site` | singleton, id `site` | none | General, Navigation, SEO, Redirects, Security, Agents, Not found, Notifications |

Names, singleton ids, route namespaces and the section set are constants in
`sanity/config/constants.ts`. Path resolution for any routed document is
`sanity/lib/document-path.ts` (`getDocumentPath`).

Security: `site.security.basicAuthEnabled` gates the whole site;
`page`/`article`/`legalPage`/`homepage` carry `security.passwordProtect`.
Site-wide wins. Credentials come from env, never from the CMS.

Agents: `site.agents.{serveLlmsTxt, llmsTxtGuidance, llmsTxt}`; every routed
document carries `agents.{serveMarkdown (default true), markdown}`. Both text
fields have a Generate button (`sanity/components/generate-*-input.tsx`) that
POSTs to the app (`/api/agents/llms-txt/generate`, `/api/agents/markdown/generate`
with `{ id }`) and writes the returned `{ llmsTxt }` / `{ markdown }` into the field.

## Sections (closed set)

One file each in `sanity/schemas/sections/`, all fields via factories, each with
its own guardrails validated before publish:

| section | required | limits |
|---------|----------|--------|
| `sectionHero` | heading | buttons max 2, media optional (custom ratio allowed) |
| `sectionRichText` | body | |
| `sectionImageText` | heading, body, media | `imagePosition` left/right |
| `sectionCta` | heading, buttons | buttons 1..2 |
| `sectionLogoGrid` | logos | 3..12 `logoItem` (image + optional link) |
| `sectionFaq` | items | 1..20 `faqItem` |
| `sectionContactForm` | heading, successMessage | |
| `sectionArticleList` | mode | `latest` + limit 1..12, or `manual` + articles |
| `sectionMedia` | media | caption max 200 |

Page types scope the set with `createPageBuilderField({ whitelist, blacklist })`:
`page`/`homepage` get everything, `article` whitelists
`sectionRichText, sectionMedia, sectionImageText, sectionFaq, sectionCta`,
`legalPage` blacklists `sectionHero, sectionLogoGrid, sectionCta, sectionContactForm, sectionArticleList`.

### Adding a section

1. `sanity/schemas/sections/section-<name>.ts` using factories only, with a `preview` and an icon.
2. Add the name to `SECTION_TYPES` in `sanity/config/constants.ts`.
3. Register it in `sanity/schemas/index-registry.ts`.
4. Add its projection to `SECTION_PROJECTIONS` in `sanity/queries/fragments/sections.ts`.
5. Run `npm run sanity:typegen`, then add the frontend component (the `plop section` generator does all of this).

## Queries

All GROQ uses `defineQuery` from `groq` and composes the fragments in
`sanity/queries/fragments/`:

- `LINK_FRAGMENT` resolves `internal->{_type, uri, slug}`; the frontend computes `href`.
- `MEDIA_FRAGMENT` returns a flat shape with `width`, `height`, `aspectRatio` for every kind.
- `RICH_TEXT_FRAGMENT` expands link annotations and inline media. Use as `field[]${RICH_TEXT_FRAGMENT}`.
- `SEO_FRAGMENT`, `PAGE_BUILDER_FRAGMENT` (one projection per section).

Document queries live in `sanity/queries/documents/`: homepage, page (`PAGE_BY_URI_QUERY`,
`PAGE_URIS_QUERY`), article, legal, site (`SITE_QUERY`, `SITE_SECURITY_QUERY`,
`REDIRECTS_QUERY`, `LLMS_TXT_QUERY`), agents (`MARKDOWN_BY_PATH_QUERY`,
`AGENT_INVENTORY_QUERY`, `ROUTED_PATHS_QUERY`, `DOCUMENT_FOR_SERIALIZER_QUERY`),
sitemap (`SITEMAP_QUERY`, `FEED_QUERY`).

## Types

`npm run sanity:typegen` runs `sanity schema extract --enforce-required-fields`
(to `sanity-schema.json`) and `sanity typegen generate` (to
`sanity/sanity.types.ts`, committed). Configuration is in `sanity-typegen.json`.
With `overloadClientMethods`, `client.fetch(QUERY)` is typed from the query.
