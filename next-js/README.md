# Content Architecture Kit, Next.js edition

An open, MIT-licensed reconstruction of an agent-ready Sanity starter.
Next.js 16 (App Router, React Compiler, Tailwind 4, Biome) in front of a
decoupled Sanity v6 workspace. The architecture is documented in
[`../docs/architecture.md`](../docs/architecture.md); this README covers the
edition.

## Features

- **Basic auth** for staging: one toggle on the Site document gates the whole
  site, a per-page toggle covers single routes. Credentials stay in env.
- **llms.txt** owned by editors: drafted from the site's own pages with
  Sanity Agent Actions, reviewed in the Studio, served verbatim at `/llms.txt`.
- **Agent Markdown**: every page answers in clean Markdown on its own URL
  when a request sends `Accept: text/markdown`. Generated by a deterministic,
  factory-name driven serializer, stored per page, toggled per page.
- **Real 404s**: unknown paths get a genuine 404 status, plus a Markdown
  recovery map for agents.
- **openapi.json** describing the public surface, including the error shape.
- **CMS-managed redirects** resolved in the proxy with a 60 second cache.
- **Umami analytics** and **spam prevention** (honeypot, HMAC timing token,
  rate limit) on the contact form, which stores submissions in Sanity and
  emails through Resend.
- **Plop generators** for sections, routes and features.
- **Seed dataset** imported by the setup script so the first run has content.
- **Contact form** built from compound form primitives with react-hook-form
  and zod.
- **Mantine hooks** for breakpoints, touch and reduced motion; `motion` for
  reveals; Lenis smooth scroll; React `<ViewTransition>` on navigation.
- **SEO**: metadata inherited from site defaults, auto-cropped OG images,
  sitemap, RSS, robots.txt with an AI-training policy, JSON-LD.
- **Fetch layer** that does not drift: CDN off in production, tagged
  `force-cache` fetches, webhook-driven `revalidateTag`, draft mode with
  Presentation and Visual Editing.

## Getting started

See [GETTING-STARTED.md](GETTING-STARTED.md) for the step-by-step path from a
fresh clone to the first rendered section.

### Prerequisites

- Node 24 (pinned in `.nvmrc`; `engine-strict` is on)
- npm
- A Sanity account (free tier is fine)

### Installation

```bash
nvm use
npm install
cp .env.example .env
npm run sanity:project-setup   # creates the project, tokens, webhook, imports seed/
npm run dev
```

Open `http://localhost:3000` for the site and `http://localhost:3000/studio`
for the Studio.

### Environment variables

All variables are validated in `env.ts` (`@t3-oss/env-nextjs`). See
`.env.example` for the full list with comments. The important ones:

| Variable | Purpose |
|----------|---------|
| `NEXT_PUBLIC_URL` | Public origin for canonical URLs, OG and sitemap |
| `NEXT_PUBLIC_SANITY_PROJECT_ID`, `NEXT_PUBLIC_SANITY_DATASET` | Sanity project |
| `SANITY_API_VIEW_TOKEN` | Viewer token for drafts and Presentation |
| `SANITY_API_EDIT_TOKEN` | Editor token for submissions and agent writes (server only) |
| `SANITY_REVALIDATE_SECRET` | Shared secret for the `/api/revalidate` webhook |
| `BASIC_AUTH_USER`, `BASIC_AUTH_PASSWORD` | Basic auth credentials |
| `FORM_SECRET` | Signs the contact form timing token |
| `RESEND_API_KEY`, `RESEND_FROM` | Contact notifications (optional) |
| `NEXT_PUBLIC_UMAMI_WEBSITE_ID`, `NEXT_PUBLIC_UMAMI_SRC` | Analytics (optional) |

Set `SKIP_ENV_VALIDATION=1` to bypass validation in CI lint jobs.

### Scripts

| Script | What it does |
|--------|--------------|
| `npm run dev` | Next dev server on port 3000 |
| `npm run build` / `npm start` | Production build and server |
| `npm run check` | Biome lint + format, writing fixes |
| `npm run lint` | Biome, read-only |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run plop` | Generators: `section`, `route`, `feature` |
| `npm run sanity:typegen` | Extract the schema and regenerate `sanity/sanity.types.ts` |
| `npm run sanity:project-setup` | Interactive project bootstrap |
| `npm run sanity:backup` | Export the dataset to `backups/<date>.tar.gz` |
| `npm run sanity:copy-dataset` | Copy a dataset (`--from`, `--to`) |

## Layout

```
app/          App Router routes (thin: fetch + render)
features/     feature modules, one concern each (see docs/features)
sanity/       decoupled Studio workspace, byte-identical with the Astro edition
proxy.ts      basic auth, redirects, markdown negotiation, real 404s
env.ts        the only place process.env is read
docs/features per-feature documentation
.claude/skills scoped skills for coding agents
```
